# React Practice — каталог игроков

Стартовый проект для одной практики по React: состояние, props, callbacks,
разделение ответственности и CSS Modules. Роутер и API пока не используются.

## Запуск

Проверенная версия Node.js: **22.22.2**, записана в `.nvmrc`.

```bash
npm ci
npm run dev
```

Откройте адрес из терминала. При использовании nvm перед установкой зависимостей:

```bash
nvm install
nvm use
```

## Как начать и сдать работу

1. Откройте https://github.com/zaharenkoliza/react-practice и нажмите **Fork**.
2. Склонируйте свою копию, подставив свой логин вместо YOUR_LOGIN:

   ```bash
   git clone https://github.com/YOUR_LOGIN/react-practice.git
   cd react-practice
   git switch -c practice-2
   npm ci
   npm run dev
   ```

3. Выполняйте [задание](PRACTICE_2.md), сохраняйте осмысленные этапы:

   ```bash
   git add src
   git commit -m "Выделить панель фильтров"
   git push -u origin practice-2
   ```

   Если намеренно добавили другие файлы, включите их в коммит отдельно.

4. В GitHub откройте pull request: **base repository** `zaharenkoliza/react-practice`,
   **base** `main`, **head repository** ваша копия, **compare** `practice-2`.
5. Назовите PR `Практика 2 — Имя Фамилия — Группа` и заполните шаблон.
   Можно сразу открыть **Draft pull request**, пока работа ещё не закончена.
6. Следующие `git commit` и `git push` в эту же ветку автоматически обновят PR.
   На каждый новый коммит открытого PR запускаются проверки.

Приглашение в репозиторий преподавателя не нужно. `main` остаётся стартовым проектом;
студенческие решения преподаватель смотрит в отдельных PR и не объединяет друг с другом.
GitHub может попросить преподавателя одобрить первый запуск проверок внешнего участника.

## Проверки

```bash
npm run check          # lint + 7 тестов старого поведения + production-сборка
npm run test:practice  # 6 требований новой практики
npm run test:all       # все 13 тестов
npm run test:watch     # тесты в режиме наблюдения за изменениями
```

**На стартовом коде `npm run check` проходит, а `test:practice` падает.**
Это ожидаемо: новые требования ещё предстоит реализовать. Не удаляйте и не пропускайте
тесты; исправляйте приложение. По завершении практики должны проходить обе группы.
В PR результаты находятся во вкладке **Checks**, подробности — внутри каждого job.

Тесты проверяют поведение приложения. Архитектуру и оформление преподаватель оценивает
по коду и интерфейсу. Детали организации занятия — [преподавателю](docs/TEACHER.md).
