# React Practice

Учебный проект по React, который мы развиваем на практических занятиях в течение семестра.
На одном приложении разбираем новые темы и постепенно улучшаем код.

Сейчас в приложении есть список игроков, поиск по имени, фильтр «только онлайн»,
сортировка и переключение статуса. Стили компонентов находятся в CSS Modules.
На следующих занятиях добавим маршруты и тесты. Новые библиотеки устанавливаем
вместе на соответствующей паре.

## Запуск

Нужен Node.js 22.22.2 (версия указана в `.nvmrc`).

```bash
npm ci
npm run dev
```

Откройте адрес, который появится в терминале.

## Работа на паре

Можно писать код вместе с преподавателем или следить за объяснением.
После демонстрации преподаватель публикует общий код и сообщает тег — имя
конкретной версии проекта. Добавляем этот код в свою ветку и выполняем задание.

Если преподаватель пригласил вас в репозиторий, примите приглашение и склонируйте его:

```bash
git clone https://github.com/zaharenkoliza/react-practice.git
cd react-practice
git switch -c YOUR_NAME
```

Замените `YOUR_NAME` на своё имя и фамилию латиницей без пробелов, например
`ivanov_ivan`. Выберите уникальное в группе название. На обе пары используем
одну ветку и один PR. Команду `git switch -c YOUR_NAME` выполняем только один раз.

Если приглашения нет, сделайте **Fork**, склонируйте свою копию и добавьте
общий репозиторий как источник обновлений:

```bash
git clone https://github.com/YOUR_LOGIN/react-practice.git
cd react-practice
git remote add upstream https://github.com/zaharenkoliza/react-practice.git
git switch -c YOUR_NAME
```

После клонирования выполните `npm ci` и `npm run dev`.

## Самостоятельное задание и сдача

Перед получением общего кода сохраните свои изменения коммитом. Сначала посмотрите
`git status`, добавьте изменённые файлы и выполните `git commit`. Если изменений
нет, коммит не нужен.

Оставаясь в своей ветке `YOUR_NAME`, получите общий код и объедините его
со своей работой. Например, после объявления тега `routing-demo`:

```bash
git fetch origin --tags
git merge --no-edit routing-demo
npm ci
```

Если работаете через fork, вместо `git fetch origin --tags` выполните
`git fetch upstream --tags`. Свои изменения отправляйте в `origin` — свой fork.

Если Git сообщил о конфликте, покажите `git status` преподавателю и вместе
исправьте конфликтующие файлы, затем добавьте их через `git add` и выполните
`git commit --no-edit`. Не отправляйте код с маркерами конфликта.

После выполнения задания:

```bash
npm run lint
npm run build
git add src
git commit -m "Выполнить задание по роутингу"
git push -u origin YOUR_NAME
```

Если меняли файлы вне `src`, добавьте их в коммит отдельно.
При установке библиотеки в коммит включаются и `package.json`, и `package-lock.json`.

Откройте **Pull request** из своей ветки в `main` репозитория
`zaharenkoliza/react-practice`. В названии укажите группу и имя.
В описании заведите разделы «Роутинг» и «Тесты»: что готово и что пока не работает.
Можно отправлять незавершённую работу. Следующие коммиты в эту ветку
автоматически появятся в том же PR. Самостоятельно вливать PR не нужно.

На второй паре продолжайте работать в `YOUR_NAME`: получите теги через
`git fetch origin --tags`, выполните `git merge --no-edit tests-demo` и `npm ci`.
Перед этим сохраните свои изменения коммитом. После задания и проверок
выполните `git push`: новые коммиты дополнят тот же PR. Преподаватель оставляет
PR открытым до проверки обеих работ. Для форка теги получаем из `upstream`.

## Проверки

`npm run lint` запускает ESLint, `npm run build` собирает приложение.
GitHub Actions выполняет эти же проверки для PR и изменений в `main`.
Результат и сообщения об ошибках находятся во вкладке Checks вашего PR.

На занятии по тестам вместе добавим `npm run test` и включим его в CI.
