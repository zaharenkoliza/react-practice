# Практика 2. Архитектура каталога игроков

Одна пара, ориентир — 90 минут. Продолжаем проект с прошлой пары.
Цель: сохранить рабочее поведение и разделить код по ответственности.

## Исходное поведение

В приложении есть Anna и Kate онлайн, Max офлайн, поиск по имени и переключение статуса.
Включите «только online», выключите статус всех видимых игроков: вместе с результатами
исчезнет и кнопка фильтра. Это первая проблема, которую исправляем на занятии.

## Что должно получиться

1. Фильтры видны даже при пустой выдаче.
2. Поиск работает по части имени без учёта регистра и пробелов по краям запроса.
3. Статус: все, онлайн, офлайн.
4. Сортировка: исходный порядок и по имени по возрастанию.
5. Поиск, статус и сортировка применяются одновременно.
6. Кнопка «Сбросить» возвращает пустой поиск, все статусы и исходный порядок.
   Она отключена, когда фильтры уже имеют начальные значения.
7. Сброс фильтров не отменяет изменения статусов игроков.
8. Карточки и панель фильтров оформлены через CSS Modules; на 375 px нет горизонтальной прокрутки.

Сохраняем исходных трёх пользователей и их начальные статусы. Расширение данных и
дополнительные функции оставляем после выполнения основной практики.

## Шаги

1. Выделите `UsersPage`, перенесите в неё состояние экрана. В `App` останется сборка приложения.
2. Выделите `UserFilters`; передавайте значения и callbacks через props.
3. Оставьте `UserList` отображение готового списка, карточек и пустого состояния.
4. Обновляйте пользователя по id без мутации массива и объектов, используя функциональное обновление state.
5. Добавьте статус и сортировку. Вынесите чистую функцию `filterAndSortUsers`.
6. Подключите CSS Modules к компонентам.
7. Самостоятельно добавьте сброс фильтров и проверьте сочетания действий.

`visibleUsers` вычисляйте из пользователей и фильтров во время рендера.
Не нужно хранить его в отдельном `useState` или синхронизировать через `useEffect`.
Держите исходный порядок пользователей неизменным: `sort()` меняет массив,
но после `filter()` можно сортировать полученный новый массив.

## Ориентир по структуре

```text
src/
  components/
    UserCard/      # JSX + CSS Module
    UserFilters/
    UserList/
  data/users.js
  pages/UsersPage/
  utils/filterAndSortUsers.js
  App.jsx
  main.jsx
  index.css
```

Названия файлов и папок не проверяются автоматически. Важно объяснить ответственность
каждой части. Устанавливать роутер, Context или библиотеку управления состоянием не нужно.

## Контракт интерфейса для автоматических проверок

Тесты используют подписи и семантику HTML, а не CSS-классы или внутреннее состояние:

- поле поиска имеет доступное имя `Поиск по имени` через `<label>` или `aria-label`;
- select `Статус`: значения option `all`, `online`, `offline`;
- select `Сортировка`: значения option `default`, `name`;
- кнопки `Сбросить` и `Изменить статус`;
- карточка — `<article>`, имя игрока — `<h2>` внутри карточки;
- статус — текст `Онлайн` / `Офлайн` (старое написание `Оффлайн` также поддерживается);
- при пустом списке — `Игроки не найдены` или стартовый текст `Никого нет`.

Свяжите видимые подписи с полями: например, вложите select в `<label>` вместе с текстом.
Соблюдение контракта делает интерфейс понятным и доступным, а тесты переживают рефакторинг.
